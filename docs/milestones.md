# Milestone status

SlopZap has a tested development alpha with onboarding, five fixture-tested adapters, conservative scoring and local storage. Implementation and release acceptance are separate: a completed code path does not establish independent classifier accuracy, live compatibility or reference-machine performance. This status follows SPEC.md §35 and the implementation decisions in §42.

## Current external checks

The latest local development verification passed 519 unit tests and 56 Chromium tests. Message-boundary regressions cover malformed batches and control messages without preference changes; cache regressions reject corrupt corrections, mismatched fingerprints, arbitrary classifier-version text and undeclared stored fields. Diagnostic labels require primitive allowlisted strings. DOM tests cover editor/private transitions, restoration, reparenting and a trusted-click privacy race without additional inference. Reference-guidance regressions cover literal quotations, weak phrase cues, paired retrieval, prompt construction, feature-version compatibility and no automatic hiding. The [paired model comparison](model-comparison.md) tests alternating arms, fresh sessions, deadlines, cancellation and numeric exports with mocks. Additional tests reproduce the real numeric snapshot's per-run metrics, confirm ordinary prompts omit guidance, reject content/malformed live diagnostics, and verify authentication-route cleanup/restoration. The [targeted boundary review](security-review-2026-10-08.md) also records immutable CI action pins and disabled persisted checkout credentials. These checks do not replace manual security signoff or independent classifier evaluation.

## Finishing release acceptance

The [reviewed classification contract](../evaluation/README.md#classification-release-evidence) adds 99 unit/CLI regressions. Schema-version-2 evaluations and release checks now share fixed statistical gates, all eighteen required slices, count/rate consistency, uncertainty validation and counted platform/type coverage. Release acceptance also requires the complete tested package map and exact deployed classifier version. The [unapproved wrapper](classification-review-template.json) contains no evaluation. Invented aggregate tests are not corpus evidence; the heuristic, automatic-hiding policy and eight outstanding acceptance gates remain unchanged.

The [reviewed performance contract](benchmarking.md#reviewed-performance-evidence) adds 93 unit/CLI regressions. It requires the tested package's complete file map, six distinct thirty-minute controls, finite measurements for every applicable SPEC budget, paired frame comparisons and explicit review of attribution and reference hardware. An [unapproved template](performance-review-template.json) keeps missing measurements null. Legacy flag-only reports, short diagnostics, stale builds and missing controls cannot approve performance. Production behavior and all eight outstanding independent/manual release gates remain unchanged.

The [idle renderer CPU diagnostic](benchmarking.md#idle-renderer-cpu-diagnostics) adds forty-two unit cases and two browser controls. An initial one-minute-per-control run exposed about 76% renderer-thread CPU in all 4× cases, including extension absent; active CPU emulation was the confound. The corrected collector resets emulation before settling and accounting, while preserving 1×/4× preceding scroll phases. Six corrected ten-second Chrome samples passed quiet-endpoint and counter checks. The [numeric snapshot](idle-cpu-results-2026-10-09.json) retains both corrected and original observations. These M5 Pro main-thread measurements do not establish worker CPU, extension-only attribution or reference-machine acceptance.

Current-package release binding adds forty-eight unit/CLI regressions. The reproducibility gate now requires the exact current packaged file names and hashes, not an “identical” flag from an unrelated build. A shared bounded scanner serves benchmarks, two-build reproduction and release checks; all 28 packaged files remain reproducible and the existing aggregate fingerprint is unchanged. Thirty short benchmark scenarios and 54 browser tests pass. These checks tighten artifact integrity without changing production behavior or the eight outstanding independent/manual release gates.

Probe connection hardening adds thirty-five unit regressions for bounded worker discovery and attachment, terminal connection failures, late replies, concurrent connections, idempotent cleanup and invalid deadlines. A stalled or uncertain attachment aborts its disposable scenario; it cannot silently become a reusable session or a successful cleanup. The real toolbar's fifteen checks and six combined worker/DOM scenarios per Chrome/Chromium remain passing. Production runtime, permissions and release approval are unchanged.

The optional [detached DOM diagnostic](benchmarking.md#detached-dom-diagnostics) adds twenty-three unit regressions and a browser positive/negative control. Six short scenarios per browser passed in installed Chrome and bundled Chromium, yielding twelve valid numeric samples per browser with zero detached trees or retained nodes before and after cleanup. A separate installed-Chrome control detected a deliberately retained two-node invented tree and returned zero after release. Fresh sessions, strict projection and deadlines keep unavailable evidence distinct from measured zero. This tooling changes no production runtime or permissions and does not replace thirty-minute retention/retainer-path review on reference hardware.
