# Milestone status

SlopZap has a tested development alpha with onboarding, five fixture-tested adapters, conservative scoring and local storage. Implementation and release acceptance are separate: a completed code path does not establish independent classifier accuracy, live compatibility or reference-machine performance. This status follows SPEC.md §35 and the implementation decisions in §42.

## Current external checks

The latest local development verification passed 141 unit tests and 53 Chromium tests. Message-boundary regressions cover malformed batches and control messages without preference changes; cache regressions reject corrupt corrections, mismatched fingerprints, arbitrary classifier-version text and undeclared stored fields. Diagnostic labels require primitive allowlisted strings. DOM tests cover editor/private transitions, restoration, reparenting and a trusted-click privacy race without additional inference. Reference-guidance regressions cover literal quotations, weak phrase cues, paired retrieval, prompt construction, feature-version compatibility and no automatic hiding. The [paired model comparison](model-comparison.md) tests alternating arms, fresh sessions, deadlines, cancellation and numeric exports with mocks. Additional tests reproduce the real numeric snapshot's per-run metrics, confirm ordinary prompts omit guidance, reject content/malformed live diagnostics, and verify authentication-route cleanup/restoration. The [targeted boundary review](security-review-2026-10-08.md) also records immutable CI action pins and disabled persisted checkout credentials. These checks do not replace manual security signoff or independent classifier evaluation.

The [accessibility validation](accessibility-review-2026-10-08.md) adds ten browser cases covering 320-pixel reflow and native 200%/400% zoom across popup, Settings, all onboarding steps and the comparison page. Narrow mocked result tables stay inside named scroll regions. Light/dark-host controls preserve accessible names, logical Tab order and host keyboard events without more classification. The popup's fixed-width overflow was reproduced and repaired. A separate installed-Chrome real-toolbar smoke now passes fifteen layout, active-tab, accessibility-state and keyboard checks on an invented discussion, with zero new classification during a saved mode switch. The [native numeric snapshot](native-toolbar-results-2026-10-08.json) remains development evidence; manual screen-reader/human browser-chrome approval is still pending.

The [architecture policy validation](architecture-review-2026-10-08.md) adds 42 unit regressions for transitive import ownership, aliases/indirect helpers, exclusion of the mock remote provider, exact manifest wiring and all seven required packaged entrypoints. Missing files, unreviewed access/contexts, oversized output and symlinks fail the build checks. These development-only changes do not alter the extension runtime or constitute manual architecture approval.

The latest tool verification passed twelve bundled-Chromium and four installed-Chrome short processing-control scenarios, with a shared packaged-build fingerprint and reproducible hashes for all 28 files. The [reference-machine handoff](benchmarking.md#reference-machine-handoff) supports four thirty-minute processing controls at 1×/4× renderer rates, but the available 15-core M5 Pro is not the original four-core reference laptop. The full long paired/reference run, worker resources, extension-absent baseline and detached-heap review remain pending. An earlier 1,000-unit virtualization diagnostic ran for 1,800.54 seconds; the last recorded post-GC heap sample at 1,740 seconds was 99.4% of the ten-minute sample, with zero remaining runtime bindings after cleanup. That diagnostic used a development build captured at run start, not a final-head paired reference-machine acceptance. Aggregate results are recorded in `docs/verification-results.json`.

On 8 October 2026, corrected isolated web probes returned `downloadable` after removing Playwright's default model-service suppressions. The packaged extension was subsequently installed in a separate isolated Chrome 155 profile using the supported developer loading command. Settings explicitly downloaded and initialized the model, and the comparison page ran three real experiments after browsing analysis was disabled. Valid pairs were 11/12, 9/12 and 11/12; every report remains incomplete. Reference benefit was not established, so guidance is developer-only and ordinary model prompts now use the baseline policy. The [numeric snapshot](../evaluation/reports/chrome-reference-2026-10-08.json) retains failures and numeric results. The test profile/model were removed; no live content or normal browser profile was accessed. Independent quality and resource acceptance remain pending.

On 8 October 2026, a corrected installed-Chrome smoke check first verified injection and local analysis on three invented units. All five public navigations then returned HTTP 200 but no target units: Reddit/Medium showed possible challenge frames, LinkedIn reached an explicitly excluded authentication route, and YouTube/X exposed no candidates. Live snapshots recorded zero bindings/classifications. The [numeric record](live-smoke-results-2026-10-08.json) is inconclusive; HTTP status and the invented control do not validate normal rendered feeds. No authentication/challenge was bypassed and no live content was saved.

The official OpenAI plan-usage flow still requires a loopback callback and keeps credentials out of browser storage. A pure MV3 extension does not satisfy that design. The mock remote contract is not shipped in a production entrypoint, and the manifest adds no network permission. See the [sign-in flow](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) and [credential guidance](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions).

## Finishing release acceptance

Supply an independently reviewed, appropriately licensed/consented corpus; run the corpus gates against the classifier actually deployed. Complete permitted live desktop checks across all five platforms. Run paired controls and 1×/4× CPU profiles on the specified reference hardware, including 30-minute heap plateau and detached-node retention. Extend the real on-device diagnostic to complete independent paired quality and resource checks, and complete screen-reader/manual accessibility checks.

Record the evidence in `docs/release-evidence.json`. `pnpm release:check` fails while evidence is missing or incompatible, rather than silently treating synthetic smoke tests as release approval. Store publication additionally requires a developer account and final submission details; the listing here remains a draft.
